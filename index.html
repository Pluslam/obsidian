Obsidian 是什麼？為什麼叫「第二大腦」

Obsidian 係一款本地優先（Local-first）嘅筆記同知識管理軟件。所有筆記都以純文字 Markdown 檔案（.md）形式儲存喺你電腦入面，唔會被鎖死喺某個雲端服務。

🧠 第二大腦

將散落喺電話、電腦、紙張、腦入面嘅想法、筆記、文件，整合成一個可以長期累積、隨時調用嘅知識系統。

🔗 雙向連結

唔係單向超連結，而係筆記之間互相知道對方引用咗自己，形成真正嘅知識網絡。

📁 你擁有資料

純文字檔案，即使用其他編輯器都可以打開。軟件倒閉都唔會影響你嘅筆記。

🔌 高度可擴展

核心功能已經好強大，再加上千個社群插件，可以打造成任何你想要嘅工具。

💡
官方定位 根據 obsidian.md/zh/：Obsidian 係「免費且靈活的應用程式，用於您的私人想法」。它強調連結、圖譜、畫布同插件，幫你「Sharpen your thinking」。

下載與安裝（影片 03:14）

官方下載頁：https://obsidian.md/download（中文站入口：https://obsidian.md/zh/）

步驟一：下載

  1. 打開瀏覽器去到 obsidian.md/download，網站會自動偵測你嘅作業系統。
  2. 選擇對應版本：
    • Windows：下載 .exe 安裝檔
    • macOS：下載 .dmg
    • Linux：提供 AppImage / Snap / Flatpak
    • 手機：iOS 去 App Store 搜尋「Obsidian」；Android 去 Google Play
  3. 如果下載速度慢（香港用戶有時會遇到），可以去 Obsidian 中文論壇 搵社群提供嘅安裝包。

步驟二：安裝同建立第一個 Vault

  1. 安裝完成後打開 Obsidian。
  2. 首次啟動會見到三個選項：
    • Create new vault（建立新庫）— 新手選呢個
    • Open folder as vault（將現有資料夾當 Vault）
    • Open vault from Obsidian Sync（付費同步服務）
  3. 點「Create new vault」，輸入名字（例如「我的知識庫」或「第二大腦」），選擇一個方便備份嘅位置（建議 Documents 資料夾）。
  4. 點擊 Create，進入主界面。
✅
Vault 係咩？ Vault 就係一個普通資料夾。入面所有 .md 檔案就係你嘅筆記，附件可以放喺同一個資料夾或子資料夾。你可以用檔案總管直接看到同管理呢啲檔案。

主屏幕按鍵與界面認識（影片 05:23）

Obsidian 主界面大致分為三個區域：

左側邊欄

檔案總管（File explorer）、搜尋、書籤、標籤面板、關係圖譜入口等。可以用滑鼠拖曳調整寬度，或者完全收合。

中間編輯區

主要寫筆記嘅地方。支援「即時預覽」（Live Preview）同「來源模式」（Source mode）。可以開多個分頁。

右側邊欄

反向連結（Backlinks）、大綱、標籤、本地圖譜等。非常重要！反向連結就喺呢度顯示。

基本設定（影片 08:12）

點左下角齒輪圖示，或者用快捷鍵打開設定。

最重要嘅幾項設定（新手優先做）

  1. 語言切換成繁體中文
    設定 → 一般（General）→ 語言 → 選擇「中文（繁體）」→ 重新啟動。
  2. 檔案與連結
    建議開啟「自動更新內部連結」（當你改名筆記時，所有引用會自動更新）。呢個功能非常重要，可以避免連結壞掉。
  3. 編輯器
    可以選擇預設「即時預覽」模式，對新手更友好。
  4. 外觀
    可以先用預設主題，之後再安裝社群主題。字體大小可以調高少少。
⚠️
刪除檔案設定 預設刪除可能係永久刪除。建議改成「移至系統回收桶」，比較安全。

雙向連結與反向連結（影片 12:25）

呢個係 Obsidian 最核心、最強大嘅功能。

點樣建立連結？

喺任何筆記入面打兩個左方括號 [[，系統就會彈出搜尋框，讓你選擇或建立新筆記：

我今日學咗 [[Obsidian 雙向連結]]，覺得好有用。

之後我可以再連結去 [[第二大腦概念]] 或者 [[Markdown 語法]]。

反向連結（Backlinks）有幾強？

  • 當你喺 A 筆記寫 [[B]]，B 筆記嘅右側「反向連結」面板就會自動顯示「A 引用咗我」。
  • 即使 B 筆記本身冇寫任何關於 A 嘅嘢，都知道有邊啲筆記提到自己。
  • 呢個功能令你嘅知識可以「互相發現」，而唔係只靠你記得去搵。
🔗
佔位符連結 你甚至可以寫一個仲未存在嘅筆記名稱，例如 [[之後要研究嘅主題]]。之後想建立嗰篇筆記時，直接點擊就可以開新檔，內容會自動連返去。

別名同標題連結

[[筆記名稱|顯示成另一個文字]]
[[筆記名稱#某個標題]]
[[筆記名稱#^某段文字的區塊ID]]

關係圖譜（Graph View）（影片 15:33）

關係圖譜將你所有筆記同連結，用視覺化網絡圖顯示出嚟。按 Ctrl/Cmd + G 或者左側圖示打開。

全域圖譜

本地圖譜

只顯示目前呢篇筆記相關嘅連結（一層或幾層）。右側邊欄通常有本地圖譜視圖。

  • 檢查有冇太多「孤兒筆記」（冇任何連結）

資料夾 vs 連結：點樣組織？（影片 16:26）

呢個係好多新手最容易糾結嘅問題。影片同社群經驗都建議：

核心原則

  • 資料夾保持淺層：最多 1–2 層就夠。唔好一開始就設計複雜分類樹。
  • 主要靠連結同標籤組織：筆記之間用 [[雙向連結]] 連接，用 #標籤 做彈性分類。
  • 筆記系統係「長」出嚟嘅：先寫，之後先整理。寫多咗自然知道邊啲需要分類。

PARA 方法（一人公司特別加強）

PARA 係 Tiago Forte 提出嘅知識組織方法，非常適合需要同時管理多間公司、多個專案嘅一人公司老闆。

P – Projects（專案）

有明確截止日期同目標嘅短期工作。例如：HADO 9 月選拔賽、Talent Academy 暑期營、某客戶 IT 專案。

A – Areas（領域）

需要長期持續維護嘅責任範圍。例如：Succeed Technology 日常營運、財務對帳、BNI 人脈、健康管理。

R – Resources（資源）

未來可能用到嘅參考資料。例如：AI 提示詞庫、幼稚園政策、Smart Sensor 規格、課程設計靈感。

A – Archives（歸檔）

已完成或暫時唔活躍嘅內容。完成嘅專案、舊會議記錄、過期資料。

重要事項如何有效 Reminder

Obsidian 本身唔係專門嘅提醒 App，但透過插件可以做到非常有效嘅任務提醒同回顧系統。

核心推薦：Tasks 插件

安裝 Tasks 插件後，你可以喺任何筆記寫：

- [ ] 完成 HADO 海報設計 📅 2026-08-15
- [ ] 跟進客戶ABC尾款 📅 2026-08-12 ⏫
- [ ] 每週財務對帳 🔁 every Friday 📅 2026-08-15

常用符號：

  • 📅 YYYY-MM-DD：到期日（Due）
  • ⏳ YYYY-MM-DD：計劃執行日（Scheduled）
  • 🔁 every week / every month on the 1st：循環任務
  • ⏫ 高優先、 🔼 中、 🔽 低

點樣令提醒真正有效

  1. 集中查看：建立一篇「任務儀表板」筆記，用 Tasks 查詢顯示： 
    ```tasks
not done
due before tomorrow
```
    同埋「本週到期」、「已過期」等查詢。
  2. 配合每日筆記：每天打開 Daily Note 時，嵌入上面嘅 Tasks 查詢，養成「每日必睇」習慣。
  3. 需要系統通知時：安裝 Reminder 插件，它支援 Tasks 格式，可以喺到期時彈出 Obsidian 通知，並可設定提醒時間。
  4. 真正重要嘅事：除咗 Obsidian 內提醒，可同時加落系統日曆（Apple Calendar / Google Calendar）或手機提醒，做到「雙重保險」。

實用範例（一人公司）

- [ ] 提交 Smart Sensor 資助申請 📅 2026-08-20 ⏫
- [ ] 準備 BNI 分享稿 ⏳ 2026-08-12 📅 2026-08-14
- [ ] 每月 cross-company 財務摘要 🔁 every month on the 1st 📅 2026-09-01
- [ ] 跟進逾期應收款 - 遊樂場協會 📅 2026-08-10
⏰
有效提醒嘅關鍵 唔係「設咗提醒就得」，而係：
1. 有到期日
2. 有固定地方每日/每週查看（Daily Note 或儀表板）
3. 重要事項有系統通知或手機提醒作後盾
4. 完成後即刻打勾，保持清單乾淨

從多個 App 匯入 Obsidian 嘅詳細步驟清單

你之前把筆記、idea、待辦、私人記錄、經驗散落喺 Google、Apple Notes、Heptabase、Microsoft Notes 等地方。呢個章節提供一套可執行、分階段嘅整合方法，避免一次過全倒造成混亂。

整體策略（最重要）

  1. 先建好 Vault 結構：用 PARA（00 Inbox、01 Projects、02 Areas、03 Resources、04 Archives）。
  2. 分階段匯入：先處理高價值 + 近期內容，舊資料慢慢搬。
  3. 全部先入 Inbox：匯入後唔好即刻分類，先集中放 00 Inbox/，之後再整理。
  4. 以 Obsidian 為最終真理來源：匯入後逐漸減少喺其他 App 寫新內容。
  5. 敏感私人記錄先手動篩選：唔好無腦全倒。

準備工作（開始前必做）

  • 安裝官方插件：Importer（設定 → 社群插件 → 搜尋 Importer）
  • 安裝 Templater（方便之後加 frontmatter）
  • 確認 Vault 已建立，並且有 00 Inbox/ 資料夾
  • 建議先做好同步 + Git 備份（參考下一章），再開始大量匯入

1. 從 Heptabase 匯入（最容易，建議先做）

  1. 喺 Heptabase Card Library 選擇想匯出嘅卡片（可多選）。
  2. 點 Export as Markdown，下載 ZIP。
  3. 解壓後，把 .md 檔案直接拖入 Obsidian 嘅 00 Inbox/ 或 03 Resources/。
  4. （進階）如果有 All-Data.json，可用社群工具（Heptabase-Export）轉成更乾淨嘅 Wiki 連結格式。
  5. 匯入後用搜尋檢查連結是否需要手動修正。

2. 從 Google Keep / Google Docs 匯入

  1. Google Keep：用瀏覽器開啟 Keep → 設定 → 匯出資料（Google Takeout 可選 Keep）。下載後通常係 HTML 或 JSON，可用第三方工具轉 Markdown，或手動複製重要筆記。
  2. Google Docs：開啟文件 → 檔案 → 下載 → 純文字 .txt 或用「Markdown 匯出」擴充功能。之後把內容貼入新筆記。
  3. 大量文件時，可先用 Google Drive 下載整個資料夾，再逐個處理高價值內容。
  4. 匯入後統一加標籤，例如 #from-google，方便之後清理。

3. 從 Apple Notes 匯入

  1. 喺 Mac 開啟「備忘錄」App。
  2. 選擇筆記 → 檔案 → 匯出為 PDF（或複製內容）。
  3. 重要筆記建議手動複製到 Obsidian，並即時加上標題同雙向連結。
  4. 大量匯出可用第三方工具（例如 Exporter 或 Shortcuts 自動化），但私人記錄建議人工篩選。
  5. 匯入後檢查有冇遺漏附件（圖片通常要另外拖入）。

4. 從 Microsoft OneNote / Notes 匯入

  1. OneNote：可匯出為 Word (.docx) 或 PDF。之後用 Pandoc 或線上工具轉成 Markdown。
  2. 較新版本有時支援直接複製內容到 Obsidian。
  3. 如果有「Microsoft Notes」App，通常只能手動複製或截圖後再整理。
  4. 建議只搬「仲有價值」嘅頁面，舊會議記錄可先留喺 OneNote 作參考。

5. 其他來源通用方法

  • 優先使用 Obsidian 官方 Importer 插件（支援 Notion、Evernote、Roam、HTML 等）。
  • 如果插件唔支援，就「匯出為 Markdown / 純文字 → 放入 Inbox」。
  • 待辦事項可集中匯入一個「Tasks Inbox」筆記，之後再用 Tasks 插件管理。

匯入後必須做的清理步驟

  1. 為每篇重要筆記加上 YAML frontmatter（type、date、company、tags、source）。
  2. 用雙向連結把相關筆記連起來（唔好只靠資料夾）。
  3. 刪除明顯重複或過時內容。
  4. 把已處理完嘅筆記由 Inbox 移去正確嘅 PARA 位置。
  5. 叫 Hermes 幫你做一次「Inbox 初步分類建議」（可用之前嘅提示詞）。

Trello 如何配合 Obsidian 使用

Trello 擅長視覺化看板同團隊協作，Obsidian 擅長深度筆記同知識連結。兩者可以分工，而唔一定要完全取代對方。

推薦配合方式

Trello 負責

視覺看板、多人協作、簡單任務流動（To Do → Doing → Done）、外部合作夥伴可見嘅進度。

Obsidian 負責

詳細說明、會議記錄、決策原因、相關知識連結、私人思考、之後俾 Hermes 讀取嘅內容。

實用整合方法

  1. 手動連結（最簡單穩定）
    喺 Obsidian 筆記入面直接貼 Trello 卡片連結：
    [Trello 卡片](https://trello.com/c/xxxxx)
    或者用雙向思維：Trello 卡片描述入面放 Obsidian 筆記連結（如果用 Obsidian Publish 或本地路徑說明）。
  2. 用社群插件「Trello」
    安裝 obsidian-trello 插件，可以用 API Token 連接 Trello 卡片到筆記，喺 Obsidian 入面睇到標籤、checklist、留言。
  3. 用 Kanban 插件代替簡單 Trello 用途
    如果主要係個人專案管理，可直接用 Obsidian 嘅 Kanban 插件，卡片本身就係 Markdown 筆記，完全本地、可被搜尋同連結。
  4. 用 n8n / Zapier 自動化
    例如：Trello 卡片移動到「Done」時，自動喺 Obsidian 建立或更新一篇完成記錄筆記。

建議工作流（一人公司）

  • 對外或需要視覺進度嘅專案 → 繼續用 Trello。
  • 每個重要 Trello 卡片對應一篇 Obsidian 筆記（放詳細內容、會議、決策）。
  • 每日或每週喺 Obsidian 用 Dataview / Tasks 查看相關待辦，而唔使成日切換 App。
  • 完成後把關鍵經驗沉澱返 Obsidian，Trello 卡片可封存。
📋
一句話 Trello 管「進度可視化」，Obsidian 管「知識同決策沉澱」。兩者用連結連接，效果最好。

Heptabase 如何配合 Obsidian 使用

Heptabase 係一款以視覺化白板 + 卡片為核心嘅知識管理工具，特別擅長做研究、概念地圖、PDF 高亮同主題整理。它同 Obsidian 可以形成很好嘅互補關係。

Heptabase 適合做咩

視覺感測、研究白板、PDF 高亮整理、卡片式原子筆記、主題地圖。當你需要「睇到全局」同空間化思考時特別強。

Obsidian 適合做咩

長期擁有嘅本地 Markdown 知識庫、雙向連結、插件生態、長文寫作、Dataview 查詢、同 AI / Hermes 深度整合。

推薦配合方式

  1. 研究階段用 Heptabase
    讀 PDF、做高亮、在白板上整理概念卡片、建立主題地圖。呢個階段重點係「理解同連結想法」。
  2. 沉澱階段匯出到 Obsidian
    當某個主題或研究告一段落，將重要卡片匯出成 Markdown，放入 Obsidian Vault（例如 03 Resources/ 或對應專案資料夾）。
  3. 日常同長期用 Obsidian
    會議、財務、每日筆記、專案追蹤、AI 處理全部喺 Obsidian 進行。Heptabase 作為「視覺思考層」，唔使取代 Obsidian。

點樣從 Heptabase 匯出到 Obsidian

  • 官方方式：喺 Card Library 選擇卡片 → Export as Markdown。匯出後會得到 .md 檔案（通常連附件），可以拖入 Obsidian Vault。
  • 完整資料匯出：Heptabase 支援匯出 All-Data.json。社群有工具（例如 Heptabase-Export）可以將卡片轉成乾淨嘅 Markdown + Wiki 連結，甚至轉成 Obsidian Canvas 檔。
  • 注意：匯出後嘅連結有時係 Heptabase 內部連結，需要手動或用腳本改成 [[筆記名]] 格式。

實用建議（適合你）

  • 用 Heptabase 做新主題研究（例如新 AI 工具、HADO 活動設計、課程大綱腦力激盪）。
  • 研究完成後，將核心卡片同結論匯入 Obsidian，並加上雙向連結同 frontmatter，方便 Hermes 之後讀取。
  • 唔好兩邊同時維護同一份筆記，避免內容漂移。以 Obsidian 作為「最終真理來源」（source of truth）。
  • Heptabase 有自動桌面備份，但仍然建議重要白板定期匯出。
🗺️
一句話總結 Heptabase = 視覺思考同研究白板；Obsidian = 長期擁有、可被 AI 讀取嘅知識庫。兩者分工，效果最好。

AI + Obsidian 整合

Obsidian 本身冇內建 AI，但因為所有筆記都係純文字 Markdown，所以非常適合同 AI 工具配合使用。呢個正正係它喺 AI 時代依然強大嘅原因。

方法一：直接複製貼上

將筆記內容複製去 Claude、ChatGPT、Grok 或 Gemini，請它總結、擴寫、產生待辦或找關聯。

方法二：AI 插件

社群有 Copilot、Smart Connections、Text Generator 等插件，可以直接喺 Obsidian 入面同 AI 對話。

方法三：外部 Agent

用 Claude Code、Cursor、或者你自己嘅 Hermes Agent，讀取 Vault 資料夾，進行批量整理或生成。

方法四：Webhook / n8n

將新筆記或每日筆記透過 n8n 自動送到 AI 處理，再寫返結果入 Vault。

[貼上筆記]

3. 用一句話總結今日重點
4. 建議呢篇筆記應該歸入邊個 PARA 分類

Dataview 入門（進階但好有用）

Dataview 係最受歡迎嘅社群插件之一，可以將你嘅筆記當成資料庫嚟查詢。

安裝

設定 → 社群插件 → 瀏覽 → 搜尋「Dataview」→ 安裝並啟用。

簡單例子

喺任何筆記入面寫以下程式碼區塊，就會自動顯示結果：

```dataview
TABLE status, due, company
FROM "01 Projects"
WHERE status = "進行中"
SORT due ASC
```

上面會列出所有「進行中」嘅專案，並顯示狀態、截止日期同公司。

```dataview
LIST
FROM #meeting
WHERE date >= date(today) - dur(7 days)
SORT date DESC
```

呢個會列出過去 7 日所有會議筆記。

📊
進階用途 你可以建立一個「儀表板」筆記，用多個 Dataview 查詢同時顯示：進行中專案、本週待辦、最近會議、未回覆嘅客戶等。非常適合一人公司日常開機第一眼就睇到全局。

Hermes Agent 點樣讀取 Vault

Hermes（你嘅一人公司大腦）同 Obsidian 非常合拍，因為 Vault 本質上就係一個普通資料夾入面嘅 Markdown 檔案。Hermes 只要有讀檔權限，就可以直接理解、搜尋同整理你嘅知識庫。

方法一：直接讀取本地 Vault 資料夾（最推薦）

如果 Hermes 跑喺你本機（Desktop）或者有檔案系統存取權限嘅環境：

  1. 喺 Hermes 嘅系統提示（Soul.md / AGENTS.md）入面明確寫低 Vault 路徑，例如： 
    你的知識庫位置：C:\Users\你的用戶名\Documents\我的第二大腦
或者 macOS/Linux：/Users/你的用戶名/Documents/我的第二大腦
  2. 畀 Hermes 工具權限讀取該資料夾（list_dir、read_file、search 等）。
  3. 之後你可以自然同 Hermes 講：
    • 「幫我搵所有關於 HADO 選拔賽嘅筆記」
    • 「總結本月 Succeed Technology 嘅會議記錄」
    • 「將 Inbox 入面未分類嘅財務筆記分類到對應公司」

方法二：用 YAML Frontmatter + 一致標籤（令 AI 更容易理解）

為咗令 Hermes 更容易準確讀取同分類，建議財務同專案筆記都用統一嘅 frontmatter：

---
type: finance / meeting / project / receipt
company: Succeed Technology / HADO / Talent Academy / VisionTouch / StoreBox
date: 2026-08-08
amount: 12800
currency: HKD
category: 收入 / 支出 / 應收 / 應付
tags: [finance, Succeed]
status: 已對帳 / 待確認
---

Hermes 可以根據呢啲欄位做過濾、統計同報表生成。

方法三：透過 n8n 或 Webhook 自動餵資料

n8n 工作流例子（Obsidian + Hermes + 財務）

n8n 非常適合做「中間層」，把 Obsidian Vault、銀行通知、Hermes Agent、Google Sheets 連接起嚟。以下係幾個實用工作流例子，你可以直接參考同修改。

工作流 1：新財務筆記自動通知 Hermes

目標：當你喺 Obsidian 新增或修改 type:finance 筆記時，自動將內容送到 Hermes 處理。

  1. Trigger：Local File Trigger 或 Webhook（如果用 Obsidian 插件發出 webhook），監控 Vault 入面 **/財務*/** 或特定資料夾。
  2. Filter：只處理含有 type: finance 嘅 .md 檔案。
  3. Read File：讀取筆記完整內容（包括 frontmatter）。
  4. HTTP Request / Telegram：將內容 POST 去 Hermes 嘅 webhook 或 Telegram bot，附帶指令例如「請分類呢筆財務記錄並更新對應公司摘要」。
  5. （可選）Hermes 處理後回傳結果，再用 n8n 寫返一篇「AI 處理結果」筆記入 Vault。

工作流 2：每月自動產生跨公司財務摘要

目標：每月 1 號自動掃描上月所有財務筆記，叫 Hermes 產生摘要，並寫入 Vault。

  1. Cron：每月 1 號 09:00 觸發（時區設為 Asia/Hong_Kong）。
  2. Read multiple files：讀取 Vault 入面所有符合條件嘅 finance 筆記（可以用 Execute Command 跑 find 或用 n8n 嘅檔案節點）。
  3. Aggregate：將內容整合成一個大 prompt。
  4. Call Hermes / LLM：送出提示詞「請根據以下財務筆記，按公司產生上月收入、支出、淨額同重要事項摘要，用指定模板格式輸出」。
  5. Write File：將 Hermes 回傳嘅 Markdown 寫入 02 Areas/財務與對帳/2026-07-月度摘要.md。

工作流 3：銀行郵件 / 通知 → 建立財務筆記草稿

目標：收到銀行轉帳通知郵件後，自動建立一筆財務筆記草稿，等你確認。

  1. Email Trigger（IMAP）或 Gmail Trigger：監控指定銀行通知郵件。
  2. Extract：用 Regex 或 AI 節點抽出金額、日期、對方、參考編號。
  3. Create File：喺 Vault 嘅 Inbox 或財務資料夾建立一篇用「銀行轉帳模板」填好嘅 .md 檔案。
  4. Notify：Telegram 通知你「有新財務草稿，請確認同補充公司分類」。

工作流 4：Google Sheets 對帳結果同步返 Obsidian

你之前有用 n8n 合併多個 Google Sheets。可以再加一步：當對帳完成後，將結果寫成 Markdown 筆記入 Vault，方便 Hermes 之後查閱。

同步、備份與跨裝置（加強版）

因為筆記係本地檔案，同步同備份需要自己處理。以下係 2026 年實用方案比較同推薦。

方案快速比較

方案 費用 平台 加密 版本歷史 適合誰
Obsidian Sync 約 $4–8/月 全平台 端對端 有（1–12 個月） 想最省心
iCloud 免費（容量內） 主要 Apple Apple 管理 無內建 全 Apple 生態
Syncthing 免費 桌面 + Android（iOS 需輔助） 裝置對裝置 無內建 重視私隱、技術向
Git + 插件 免費 桌面為主，手機較麻煩 視乎遠端 完整歷史 需要版本控制
OneDrive / Google Drive 視乎方案 全平台 供應商管理 有限 已有雲端習慣

推薦組合（適合一人公司 + Windows 為主）

  1. 主力同步：優先考慮 Obsidian Sync（最穩定、有版本歷史、全平台），或者 Syncthing（免費、私隱好）。
  2. 版本控制備份：另外用 Git（搭配 Obsidian Git 插件）每日自動 commit，推去私人 GitHub / Gitea 倉庫。即使同步出問題，都可以還原任何版本。
  3. 離線冷備份：每星期或每月將整個 Vault 壓縮，複製去外置硬碟或另一個雲端（唔同供應商）。

重要注意事項

  • 永遠只選一種同步引擎：唔好同時開 Obsidian Sync + iCloud + Syncthing，好容易產生衝突同損壞檔案。
  • 財務同敏感筆記建議開啟 Obsidian 嘅加密插件，或者將整個 Vault 放喺加密容器（例如 VeraCrypt）。
  • 手機端（iOS/Android）同步通常係最容易出問題嘅地方，建議先喺桌面穩定後先加手機。
  • 同步前養成「關閉 Obsidian → 等同步完成 → 再開」嘅習慣（尤其用雲端資料夾時）。
